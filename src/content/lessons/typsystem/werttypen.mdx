<Block n={1} title="Das Problem">

Stell dir vor, jede Zahl in deinem Programm wäre ein eigenes Objekt auf dem Heap. Ein `int` bräuchte dann einen Object Header, einen MethodTable-Zeiger und eine Allokation. Jede Rechnung müsste erst einem Verweis folgen, und der Garbage Collector müsste Milliarden winziger Objekte verwalten. Für kleine, häufig benutzte Werte wäre das absurd teuer.

Umgekehrt brauchst du für viele Dinge genau diese Objekte. Ein Kunde, eine Bestellung, ein offener Datenstrom: Mehrere Programmteile sollen auf **dasselbe** Ding zugreifen und Änderungen gegenseitig sehen. Sie sollen polymorph sein, also über eine Basisklasse oder ein Interface angesprochen werden. Und sie sollen leben, solange jemand sie braucht, nicht nur so lange wie die Methode, die sie erzeugt hat.

.NET löst diesen Zielkonflikt, indem es dir die Wahl lässt. **Werttypen** (`struct`, alle Zahlentypen, `bool`, `char`, `enum`) sind reine Daten ohne Identität. **Referenztypen** (`class`, `string`, Arrays, Delegates, Interfaces) sind Objekte mit Identität auf dem Heap. Fast jede Eigenart von C#, die mit Kopien, `null`, Gleichheit oder Performance zu tun hat, folgt aus diesem einen Unterschied.

</Block>

<Block n={2} title="Das mentale Modell">

Vier Sätze genügen:

1. **Eine Variable eines Werttyps enthält den Wert selbst.** Eine Variable eines Referenztyps enthält einen Verweis, also im Kern eine Adresse, auf ein Objekt auf dem Heap.
2. **Zuweisung und Parameterübergabe kopieren den Inhalt der Variablen.** Bei Werttypen ist das der ganze Wert, bei Referenztypen nur der Verweis. Das Objekt selbst wird nie kopiert.
3. **Ein Werttyp liegt dort, wo er deklariert ist.** Als lokale Variable im Stack-Frame oder in einem Register, als Feld einer Klasse im Objekt auf dem Heap, als Element eines Arrays im Array.
4. **Nur Referenzvariablen können `null` sein.** Ein Werttyp hat immer einen Wert, im Zweifel den Standardwert mit lauter Nullbits. `int?` ist ein eigener Werttyp mit zusätzlichem Flag.

<Callout kind="fehlannahme">
  „Werttypen liegen auf dem Stack, Referenztypen auf dem Heap.“ Nur der zweite Teil stimmt immer.
  Der Unterschied ist nicht der Ort, sondern was eine Variable enthält: den Wert oder einen Verweis.
  Wo ein Werttyp liegt, bestimmt sein Umfeld.
</Callout>

<Block n={4} title="Wo Werttypen wirklich liegen">

Satz 3 des Modells ist der, den die meisten unterschätzen. Ein Struct ist kein eigenständiges Objekt, sondern ein Stück Speicher, das in etwas anderes eingebettet wird. Das folgende Beispiel zeigt vier Umgebungen für dasselbe Struct.

<StepPlayer script={placementScript} />

Daraus ergeben sich zwei wichtige Folgen:

- **Structs als Felder vergrößern das umgebende Objekt.** `Line` enthält zwei Punkte, also vier `int`-Felder, ohne ein einziges zusätzliches Objekt. Bei einer Klasse `PointC` wären es zwei Verweise und zwei weitere Objekte.
- **Arrays von Structs sind dicht gepackt.** Für die CPU ist das ideal: Die Daten liegen hintereinander im Speicher und landen gemeinsam im Cache. Bei Arrays von Objekten muss für jedes Element erst einem Verweis an eine andere Stelle gefolgt werden.

### Lokale Variablen und Register

Auch „lokale Variable auf dem Stack“ ist eine Vereinfachung. Der JIT entscheidet selbst, wo er einen Wert hält. Kleine Werte, und oft auch die Felder kleiner Structs, landen in CPU-Registern und berühren den Stack nie. Für das Verständnis ist das Modell mit dem Stack-Frame trotzdem richtig: Der Wert gehört zur laufenden Methode und verschwindet mit ihr.

<Block n={5} title="Parameterübergabe im Detail">

Was für die Zuweisung gilt, gilt genauso für Methodenaufrufe. Ein Parameter ist eine lokale Variable der aufgerufenen Methode, die mit einer Kopie des Arguments gefüllt wird. Bei einem Struct ist das eine Kopie des ganzen Werts, bei einer Klasse eine Kopie des Verweises.

<StepPlayer script={paramsScript} />

### ref, in und out

Willst du, dass eine Methode die Variable des Aufrufers selbst verändert, übergibst du sie mit `ref`. Dann wird nicht der Inhalt kopiert, sondern ein Verweis auf die Variable übergeben, ein sogenannter verwalteter Zeiger:

```csharp
static void Reset(ref PointS s) => s.X = 0;      // ändert die Variable des Aufrufers
static void Replace(ref PointC k) => k = new PointC(); // ersetzt das Objekt beim Aufrufer

var p = new PointS { X = 1 };
Reset(ref p);                                    // p.X ist jetzt 0
```

`out` funktioniert ebenso, verlangt aber, dass die Methode einen Wert zuweist. `in` übergibt ein Struct per Verweis, verbietet aber Änderungen. Das lohnt sich bei großen Structs, deren Kopie teuer wäre.

</Block>

<Block n={6} title="Stolperfallen">

### Structs in Listen ändern

```csharp
var arr = new PointS[1];
arr[0].X = 5;              // funktioniert: das Element wird direkt geändert

var list = new List<PointS> { new() };
list[0].X = 5;             // Compilerfehler CS1612
```

Der Unterschied liegt im Zugriff. Ein Array-Element ist eine echte Speicherstelle, `arr[0].X = 5` schreibt direkt hinein. Der Indexer von `List<T>` dagegen ist eine Methode, die eine **Kopie** des Elements zurückgibt. Eine Änderung an dieser Kopie wäre sofort verloren, deshalb verbietet der Compiler sie. Du musst das Element lesen, ändern und zurückschreiben.

### Gleichheit

`==` und `Equals` bedeuten bei den beiden Typarten Verschiedenes. Bei Klassen vergleicht `==` standardmäßig die Verweise, also die Identität: Zwei Objekte mit gleichem Inhalt sind nicht gleich. Bei Structs vergleicht `Equals` standardmäßig den Inhalt, allerdings über eine allgemeine Implementierung in `ValueType`, die langsam sein kann. Wer Structs vergleicht, sollte `IEquatable<T>` implementieren oder gleich ein `record struct` verwenden, das diese Methoden erzeugt.

### Große Structs

Weil jede Zuweisung und jeder Aufruf das ganze Struct kopiert, werden große Structs schnell teurer als Klassen. Die Entwurfsrichtlinien von Microsoft nennen als Faustregel Instanzen unter 16 Byte. Das ist kein hartes Limit, aber ein guter Hinweis, ab wann man genauer hinsehen sollte.

</Block>

<Block n={7} title="In der Praxis: struct oder class?">

| Eigenschaft                 | struct                       | class                                     |
| --------------------------- | ---------------------------- | ----------------------------------------- |
| Variable enthält            | den Wert                     | einen Verweis                             |
| Zuweisung, Parameter        | kopiert den Wert             | kopiert den Verweis                       |
| Allokation                  | keine eigene, eingebettet    | eigenes Objekt auf dem Heap               |
| Kosten pro Instanz          | nur die Felder               | Felder plus Header und MethodTable-Zeiger |
| `null` möglich              | nein (nur mit `Nullable<T>`) | ja                                        |
| Identität                   | keine                        | ja, `ReferenceEquals`                     |
| Vererbung                   | nein, nur Interfaces         | ja                                        |
| Als `object` oder Interface | wird geboxt                  | direkt                                    |

Ein Struct passt gut, wenn ein Typ einen kleinen Wert darstellt, logisch unveränderlich ist und selten als `object` oder Interface benutzt wird: Koordinaten, Geldbeträge, Zeitspannen, Schlüssel aus mehreren Teilen. Eine Klasse passt, sobald Identität, Vererbung, gemeinsamer veränderlicher Zustand oder größere Datenmengen im Spiel sind. Im Zweifel ist eine Klasse die sichere Wahl. Wie sich das Boxing von Structs auswirkt, zeigt die Lektion „Boxing und Unboxing“.

</Block>

<Block n={10} title="Das Wichtigste in Kürze">

- Werttypen enthalten ihren Wert, Referenztypen einen Verweis auf ein Objekt auf dem Heap.
- Zuweisung und Parameterübergabe kopieren immer den Inhalt der Variablen: den Wert oder den Verweis.
- Ein Werttyp liegt dort, wo er deklariert ist: im Stack-Frame, in einem Register, im umgebenden Objekt oder Array.
- Arrays von Structs sind ein einziges, dicht gepacktes Objekt. Arrays von Klassen enthalten Verweise auf viele Objekte.
- Referenzen werden per Wert übergeben. Nur `ref` und `out` geben der Methode Zugriff auf die Variable des Aufrufers.
- Structs eignen sich für kleine, unveränderliche Werte. Für Identität, Vererbung und gemeinsamen Zustand sind Klassen da.

</Block>
